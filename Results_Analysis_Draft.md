# ChainWatch: Results Analysis and Risk Evaluation Methodology

This document outlines the results analysis methodology for the ChainWatch project, detailing what data is obtained, the architecture for gathering these results, and the specific algorithms used to calculate the supply chain risk scores.

## 1. Expected Results (What Results Are We Getting?)

ChainWatch provides a comprehensive, real-time supply chain risk assessment for targeted port regions (e.g., Shanghai, Rotterdam, Los Angeles). The primary results obtained from the system include:

*   **Aggregated System State**: A unified dashboard view consisting of a final computed **Risk Score (1.0 - 5.0)** and a categorized **Risk Level (Low, Medium, High)**.
*   **Live Port & Vessel Metrics**: Real-time maritime data within a port's bounding box, yielding metrics such as the total vessel count, the number of stationary vs. moored vessels, average vessel speed, and ship type breakdowns.
*   **Weather Conditions**: Current and forecasted weather metrics tailored to the port region, including temperature (°C), wind speed (km/h), and precipitation (mm).
*   **Supply Chain News Intelligence**: Summarized recent news events impacting the region, classified by event type and severity, accompanied by their source citations.
*   **AI-Generated Explanations**: A qualitative, natural language summary generated by an LLM that explains *why* the current risk score is what it is, synthesizing the news, weather, and port congestion factors.

## 2. Data Acquisition Architecture (How Are We Getting Results?)

The backend employs an orchestration architecture with multiple specialized **Agents** that fetch, process, and evaluate data concurrently.

1.  **Port Risk Agent**: Interacts with the `AISStreamService` to sample live Automatic Identification System (AIS) vessel data for 15-30 seconds over a configured bounding box. It tracks moving, moored, and stationary ships.
2.  **Weather Risk Agent**: Calls the `WeatherAPIClient` to retrieve current and forecast meteorological conditions for the target region.
3.  **News Risk Agent**: Uses the `NewsAPIClient` to fetch recent supply chain and maritime news articles relevant to the region.
4.  **Orchestrator**: Acts as the central pipeline controller. When a region is queried, the Orchestrator runs the News, Weather, and Port agents to gather granular outputs.
5.  **Aggregation Agent**: Receives the raw severity metrics from the other agents and computes the final weighted risk score.
6.  **Explanation Agent**: Takes the full aggregated state and passes it to an LLM service (`LLMService`) to generate a human-readable justification of the risk assessment.

## 3. Risk Score Evaluation Methodology (How is the Risk Score Evaluated?)

The system evaluates risk using a multi-layered approach. Each specialized agent computes its own localized **Severity Score ranging from 1 to 5**, which are then combined.

### 3.1 Port Severity Algorithm
The Port Agent calculates severity based on the density and movement of vessels:
*   **Base Severity via Vessel Count**:
    *   $\ge 50$ vessels: Critical (5)
    *   $\ge 26$ vessels: High (4)
    *   $\ge 11$ vessels: Moderate (3)
    *   $\ge 5$ vessels: Low-Moderate (2)
    *   $< 5$ vessels: Low (1)
*   **Congestion Modifier**: The algorithm calculates a **stationary ratio** (Stationary Vessels / Total Vessels). If the stationary ratio exceeds **60% (0.6)**, which indicates a backlog or anchorage queue, the base severity is incremented by **+1** (capped at a maximum of 5).

### 3.2 Weather Severity Algorithm
The Weather Agent uses deterministic thresholds based on the worst-case scenario between current conditions and near-term forecasts:
*   **Rainfall**: $\ge 80$mm (5), $\ge 50$mm (4), $\ge 30$mm (3), $\ge 10$mm (2)
*   **Wind Speed**: $\ge 80$km/h (5), $\ge 60$km/h (4), $\ge 40$km/h (3), $\ge 25$km/h (2)
*   **Temperature Extremes**: $\le 0$°C or $\ge 40$°C automatically triggers a severity of (4).
The final Weather Severity is the **maximum** value triggered by any of the above conditions.

### 3.3 News Severity Algorithm
The News Agent utilizes a Large Language Model (LLM) classification step. Read supply chain articles are fed into the LLM, which is prompted to analyze the text and output a perceived risk severity score between 1 (Normal) and 5 (Critical Interruption).

### 3.4 Aggregation and Final Score
The `AggregationAgent` computes the final expected **Risk Score** using a weighted linear combination of the three individual severities. The weights reflect the relative impact each domain generally has on immediate supply chain continuity:

$\text{Risk Score} = (0.4 \times \text{News Severity}) + (0.3 \times \text{Weather Severity}) + (0.3 \times \text{Port Severity})$

The resulting score is rounded to one decimal place, and the **Risk Level** is categorized as follows:
*   **Low**: $0.0 \le \text{Score} < 2.5$
*   **Medium**: $2.5 \le \text{Score} < 3.5$
*   **High**: $3.5 \le \text{Score} \le 6.0$

Along with the numerical score, an `avg_delay_hours` metric is heuristically estimated based on port severity (up to 120 hours delay for Critical severity, modified upwards if total vessels exceed 40).
